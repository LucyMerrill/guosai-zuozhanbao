# 阶段⑦ 主 agent 流程：赛后复盘与战果回流

> 用法：每次比赛（国赛/华数杯/模拟赛/标定赛）结束后 **48 小时内**执行。以主 agent 亲自做为主（多为单点操作）；材料量大时可派一个 general-purpose 复盘子 agent。
> **2026-08-28 新建**：把"赛后再提炼"变成固定动作——作战包的成长史 = 技能仓库的 git log。

## 输入材料

- 工作目录下：`PROGRESS.md`、`评审报告_*.md`（含各轮整改记录节）、`check.json`、论文终稿与交付记录
- 技能目录下：现有 references/（**回流前先查重**，防止重复收录）

## 一、复盘三问（每问至少产出 1 条结论，写入 PROGRESS.md 复盘节）

1. **stage 级**：哪个阶段的提示词跑得顺？哪里卡住需要人工干预（子 agent 死循环、格式校验反复不过、衔接断裂）？
2. **规则级**：评审循环反复 FAIL/WARN 的是什么？哪些是流程漏洞（规则缺失/校验器伪放行）而非本次失误？
3. **标准级**：外部对标（获奖卷、当年评审反馈、新规通知）暴露了什么新差距？

## 二、三通道回流（每条发现只进一个通道，先查重再写）

| 发现类型 | 回流动作 | 落点 |
|---|---|---|
| 踩了新雷（语言/版式类扣分点） | 按"触发词/为什么扣分/一句话整改"格式追加条目 | 20 号雷点库 |
| 数字/逻辑类硬伤（口径打架、叙事与 JSON 冲突、表述与实现不符） | 按 24 号格式追加条目 | 24 号数字诚实性库 |
| stage 提示词缺陷（比赛中手动打过补丁） | 把补丁折回对应 stage 文件，文件头加一行日期变更注记 | stages/stageN |
| 新获奖卷 / 评审标准 / 新规 | 写对标学习报告，编号顺接；提炼出的新门禁同步进 20 号 §一 | references/NN_ |
| 流程级通用机制（防绕圈、缓存、固定模板之类） | 按 23 号"机制借鉴"格式（原理+落地映射+不借鉴清单）补入 | references/ 或 stages/ |

**判断标准（防污染，硬性）**：通用经验才进技能包；**题目特定**的发现（某题数据的坑、某问的解法、某个具体数字）留在工作区存档，禁止回流。拿不准时问一句："换个题目这条还成立吗？"不成立就不进。

## 三、收尾三件事

1. **技能仓库 git 提交**（提交信息格式：`赛后回流：<比赛名>：雷点N条/stageN修补/新增NN号`）——此后 `git log` 即作战包成长史。
2. **工作区存档不动**：原样保留评审报告、对标材料作证据链，不清理不回改。
3. **PROGRESS.md 记"已回流条目清单"**：逐条列出回流去了哪个文件哪一条，防止下次复盘重复回流。

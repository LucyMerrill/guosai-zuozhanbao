### 2.1 必做

| # | 规则 | 具体做法 | 来源 |
|---|---|---|---|
| P1 | 附录三件套或按问分册二选一 | ①C050 式：列表/补图表/代码合一附录；②盐城式：按问分四个代码附录。无论哪种，代码正文必须有（G3） | 【C050】【盐】 |
| P2 | 数据预处理落位二选一 | ①独立成章五节法：异常值→缺失过滤→填充→变换→量纲统一，各节带方法理由；②并入各问 x.1 小节。二选一全篇统一，禁有章无节的空壳 | 【扬】五章法；【C050】内嵌式 |
| P3 | 检验/灵敏度不设独立大章 | 内嵌各问检验小节一次性呈现，防第七章与第十章重复叙述被判"凑页"；确需集中则改名"十、检验、灵敏度与误差分析"并删各问重复段 | 【盐】5.x.4；【扬】7.4/8.4 |

| P5 | 参数级细节入文显严谨 | 含超参、固定随机种子声明（"随机种子 R_s=0，固定种子以保证结果可复现"）；连接词用首先/其次/再次/随后/最后模板 | 【扬】参数清单式写法 |

| P7 | 无不确定性不过精度 | 结果表全套六列"变量\|系数\|标准误\|z值\|p值\|95%置信区间"；区间结果用"约"缓冲；有效数字 ≤4 位 | 【扬】表4~表8；TOP15-6 |

### 2.2 可选（加分不强制）

- 关键词 4~6 个（模板口径），分隔符空格/全角逗号/分号皆可，但**全篇统一**；用"关键词"不用"关键字"。
- 符号宜简不宜繁，尽量单字母【韩·2.5】；假设逐条附依据并被正文回收引用。
- 小标题具体化（如"7.4.2 降幅未达预设阈值的原因"）优于流水账标题——注意：【韩·2.6(i)】反对"问题N的模型建立与求解"式立题，但 G1 的同构章名是获奖卷实证范式，**两者分层适用**：一级章名守 G1 同构，二级以下小标题应具体化反映方法特点。
- 多模型须列对比表（如五种模型 R² 对比）由数据决定主模型，并写明取舍理由。

### 2.3 修订执行顺序（照做）

G5（一分钟热修）→ G3/G2/G1/G8（结构批）→ G4/G10/G7（图表批，需作图）→ G12（摘要重写）→ P3（合并去重）。G4/G10 完成后按 G7 重排全部图号，全局替换文中"图 N""见表X"引用与 figures/ 文件名引用。

## 三、写作铁律：每问六段闭环 + 语言红线

### 3.1 每问六段闭环（硬性结构要求）

每一问章节内部**必须**按以下六段组织，缺一段即结构不完整：

```
动机 → 方法 → 求解 → 结果 → 检验 → 小结
```

| 段 | 内容 | 合格标准（照做示例均出自获奖卷原文风格） |
|---|---|---|
| ① 动机 | 为什么用这个方法 | 先说数据特征再说选型："考虑到某些孕妇有多次采血的情况，所以不直接采用多元线性回归拟合，防止拟合出现问题"【盐】。禁止"建立 XX 模型如下"开场【韩·2.6(iii)】 |
| ② 方法 | 数学原理→建模过程→模型总结 | 目标函数/方程完整给出并编号；多方案先对比再定主模型【扬】 |
| ③ 求解 | 说明求解手段及为何用它 | "极大似然估计是唯一能统一处理这两种效应的框架……似然方程无解析解，故用牛顿迭代"【扬】。求解也要给理由【韩·2.6(iv)】 |
| ④ 结果 | 数字+解读成对出现 | 关键数值给到 3~4 位有效数字并翻译含义；系数类结果必须带 SE/p/CI 列 |
| ⑤ 检验 | **第二方法交叉印证 + 敏感性** | 至少一个独立于主模型的检验动作（GAM 对照/Bootstrap/蒙特卡洛扰动/贝叶斯层次交叉验证），量化到"BMI 变化 10% 导致 R² 下降 5%"幅度；负结果如实报告但说法见 §五 |
| ⑥ 小结 | 复述全过程+全部关键数字，落到建议 | 小结是给评委的"答案卡"；下一问动机与本问产出衔接（问间承接句） |

来源依据：【盐】每问五段式（建模→求解→结论→检验分析→小结）四问无一缺席；【扬】"模型准备→建立→求解→检验"同构；【韩·2.10】系统连贯性。我方在两卷基础上加"动机"独立成段。

### 3.2 语言红线（违规即评委眼中 AI 痕迹，校验器 v2 会 WARN）

| # | 红线 | 正解 |
|---|---|---|
| L1 | **禁元话语**："如实/如实归因/而非修饰/诚实/透明/预设判据/契约/预案/条款"等内部流程词不许入文 | 直接写结果数值与原因，删掉所有自我评判姿态 |
| L2 | **禁工程黑话**："口径/引擎/重放/双引擎/管道/主力/下发/基线A/B/MC模拟"等 | 回归数学统计用语："计算框架/用于/重新评估/基准规则/蒙特卡洛模拟" |
| L3 | **克制加粗范式（2026-09-05 勘误，本条 v2 旧版"禁加粗>3处"已被 17 号 §2A v3 取代）**：正文非标题加粗片段以校验器 v3 阈值为准（全文 10~400 段合法，出界 WARN；整段全加粗违规）——重点仍靠句首位置与句序，加粗只给"每问小结核心结论短语/重要中间结论"，**禁满篇强调、整句加粗、装饰性加粗** | 按 17 号 §2A：正文每页 1~4 处克制加粗；摘要按三类锚点（引领短语/主模型名/关键数字），加粗字符量约 200 对齐 C050 |
| L4 | **禁伪精度**：6 位以上有效数字且无任何不确定性 | ≤4 位有效数字；关键估计附 SE 或 95%CI 或"约"字 |
| L5 | **禁代码符号泄漏**：函数名/文件名/JSON 键入正文（grid_curve、all_results.json） | 一律改"式(n)/表(n)/附录清单"引用 |
| L6 | **禁形容词空话收尾**："效果良好/鲁棒性强/一目了然"无数字 | 空话句替换为"指标±数字"实证句 |
| L7 | **禁破折号插入语高频与多重括号嵌套**（≥2 处/页、三层括号） | 一句一意≤40 字；括号至多一层 |
| L8 | **中英混杂禁令**：Monte Carlo/POMDP 未译 | 中文译名统一，外文缩写仅首现注全称 |
| L9 | **机械排比禁令**："其一其二其三"+名词标签连用 | 用"首先/其次/最后"动词推进或自然衔接句 |

人称与时态基调（获奖卷共识）：全篇以无主语陈述为主，"本文/本问"章首可用、"我们"少量作操作主语、【盐】几乎不用"我们"；一律一般现在时陈述，无故事化叙事；数字密集但保持 2~4 位有效数字并用"约"缓冲。

### 3.3 附录代码去 AI 痕迹（v5 新增：评委也会翻代码，代码同样有 AI 指纹）

> 来源：cumcm-live-workflow 实战沉淀。正文去了 AI 味、附录代码却是"教科书式完美代码"，同样是 AI 代写信号。**红线：绝不故意制造 bug**——"不完美"只体现在注释/命名/结构痕迹，数值与功能必须正确。

| # | AI 指纹 | 对策 |
|---|--------|------|
| 1 | 教科书式注释（每行都注释、docstring 完美统一） | 只留"为什么"和踩坑记录，删"做了什么"的废话注释 |
| 2 | 命名完美主义（处处规范长命名） | 循环内允许单字母/缩写；不同文件风格允许有差异 |
| 3 | 无版本迭代痕迹 | 保留版本迭代注释（`# v2: 修正了XX边界bug`）、被注释掉的旧方案；魔法数字注明来源 |
| 4 | 输出过于规整 | 打印加非正式进度提示；验证代码内联在 `__main__` 块 |
| 5 | 文件组织过于清晰 | 保留"复制粘贴+微调"的合理冗余，不必强行抽公共模块 |
| 6 | 中英混杂特定句式 | 备注纯中文或纯英文，别一种一句 |
| ⚠ | 机器精度级数字满篇跑 | 精确数字只在验证部分出现一次；扫描区间写"对可行域内不同取值验证" |

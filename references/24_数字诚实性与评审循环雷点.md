## 三、评审循环操作经验（§一§二的问题靠这三条抓出来）

1. **每轮换视角换手段**：同一评审者连评会疲劳放水。实战节奏——第1轮按 05/08 清单+国奖打分（抓出 4F）；第2轮只查整改复发（抓半途残留）；第3轮换"终审评委"人设+新手段（解包 docx XML 数 oMath、直读 xlsx 复算清洗事实、附录代码逐行比对≈96.4% 匹配率），仍抓出 2F。评审手段清单：解包 XML 实测、直读原始附件复算、PDF 字号/行距/加粗 span 实测、代码逐行 diff、**独立复算**（关键结论不调用论文代码、从零另实现一遍对数——最强手段，专破"整套代码自洽但模型建错"）、**图文互检**（逐图核对图注数值/阈值标注/时间范围/图例单位与正文是否一致，实测最常抓到图文不符）。
2. **报告自带整改记录节**：每轮报告末尾附"整改记录"，逐条写证据（哪个键、哪个文件、重跑结果），形成证据链；下一轮评审只查复发+新问题，不重复旧条目。
3. **校验器会伪放行**：check.json 附录代码项仅凭"语法特征行"即通过（实际等宽段落 0 行）。规则：校验器每条规则都要用对抗样本自测；单特征放行的规则最多计 WARN，FAIL 级判定必须双特征。
4. **放行门槛**：致命问题=0 才能进下一阶段；"条件放行"（修完分钟级 WARN 即定稿）要列明遗留项，禁止默认通过。
5. **支撑材料对齐（2026 官方红线）**：论文附录的"支撑材料文件列表"必须与实际压缩包内容**逐一对齐**——压缩包几十个文件而附录只列几个 = 评委抓包点；打包前程序化 diff 文件清单（官方格式规范 R5）。
